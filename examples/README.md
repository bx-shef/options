# Примеры

Рабочие примеры к строительным блокам модуля. Не куски псевдокода: каждый
файл запускается и сам проверяет, что получилось именно обещанное. Разойдётся
обещание с результатом — пример падает с ненулевым кодом возврата, и это
видит CI (`tests/examples_test.php`).

## Что здесь есть

| пример | цель | где применять |
|---|---|---|
| [singleton.php](singleton.php) | унаследовать `Options\Singleton` | общий объект с состоянием в пределах запроса |
| [config.php](config.php) | реестр настроек, `push()` / `restore()` | разобрали настройку один раз; временная подмена режима |
| [smartstd.php](smartstd.php) | массив ↔ объект, глубокое клонирование | передача структур между модулями и слоями |
| [pid.php](pid.php) | блокировка процесса pid-файлом | агенты и cron, которым нельзя в два экземпляра |
| [preparefields.php](preparefields.php) | трейт `PrepareFields` | вход от человека или чужой системы |

## Как запускать

Два режима, файлы одни и те же.

**Без портала** — ядро подменяется заглушками из `tests/stub/bitrix.php`,
классы подключаются руками. Так примеры гоняет CI:

```bash
php examples/pid.php
```

**На живом Битриксе** — подключается пролог, модуль берётся
`Loader::includeModule('shef.options')`, классы находит автозагрузка. То есть
код примера ровно тот, что вы напишете у себя:

```bash
DOCUMENT_ROOT=/var/www/portal php examples/pid.php
```

Режим печатается первой строкой: `Блокировка процесса через pid-файл [портал]`.
Если там `[заглушки]`, а вы ждали портал — не нашёлся
`<DOCUMENT_ROOT>/bitrix/modules/main/include/prolog_before.php`.

Модуль на портале должен быть **установлен**, а не просто распакован: иначе
пример честно скажет `Модуль shef.options не установлен` и вернёт 1.

## Как выглядит успешный прогон

```
Блокировка процесса через pid-файл [портал]

— Процесс объявляет себя занятым
  ok   до add() файла нет = false
  ok   add() отработал = true
  ...

ГОТОВО: pid
```

Код возврата `0`. Любая строка `FAIL` означает, что код разошёлся с тем, что
обещает пример: это находка, а не шум. Ни одного `Warning`, `Notice` или
`Deprecated` в выводе быть не должно — обвязка превращает их в исключение.

## Что примеры делают с системой

Всё, кроме `pid.php`, работает только с памятью процесса.

`pid.php` пишет файлы. Без портала — во временный каталог, который сам за
собой убирает. На портале — в настоящий временный каталог
(`upload/tmp` либо `BX_TEMPORARY_FILES_DIRECTORY`), в подкаталог
`shef.options/example-pid`; все файлы пример удаляет, пустой каталог группы
остаётся. Сигналов живым процессам пример не шлёт: `removeByGroup()` зовётся
с `0`.

## Если добавляете свой пример

Шапка обязана содержать четыре раздела — их наличие проверяет тест:

```
 * ЦЕЛЬ
 * ГДЕ ПРИМЕНЯТЬ
 * ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ
 * ЗАПУСК
```

Дальше `require_once __DIR__.'/_bootstrap.php';`, `title()`, `$load()` для
классов, и по шагам: `step()` — заголовок, `note()` — пояснение,
`check()` — обещание. Заканчивать `done('<имя файла без .php>')`.

`check()` здесь главный: он превращает «должно получиться» в проверяемое
утверждение. Пример без единого `check()` — это комментарий, а не пример.
